# Gyro Capture, Part 2: iOS Runtime and SwiftUI Screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the shared iOS gyro feature in OpenCine: phone motion driver, capture coordinator (logging, session arming, ring calibration, drift), and the SwiftUI screens (pill, arming sheet, ring calibration, logs list, take page with select-and-share, post-take drift sheet) in portrait and landscape with full VoiceOver support, all driven by a fake camera adapter.

**Architecture:** A new iOS-only target `OpenCineGyroApple` (layer `core`, like `OpenCineRelayApple`: `OpenCineGyro` plus Apple frameworks) holds CoreMotion, the `UserDefaults` key-value store and the `@Observable` `GyroCaptureCoordinator` moved from OpenZCine `ios/Runner/GyroCaptureCoordinator.swift` and rebuilt on Part 1's policy types. The screens live in `OpenCineCameraControls/Gyro/` (where the other monitor sheets live), take values and actions, and a single `gyroFeature(_:)` modifier binds them to the coordinator so an app adds one modifier, one pill and one settings source.

**Tech Stack:** Swift 6, SwiftUI (iOS 17), Observation, CoreMotion, UIKit (background task, share sheet), Swift Testing, XCTest-hosted view tests in `MonitorUITests`.

**Spec:** `docs/superpowers/specs/2026-10-25-gyro-capture-ux-design.md` and mockups in `docs/superpowers/specs/2026-10-25-gyro-capture-ux-mockups/` (direction A "Fill the ring" and the logs screen; owner decisions 1 to 3 override the mockup's "Open in Gyroflow" and "Share another way").

**Depends on:** Part 1 (`docs/superpowers/plans/2026-10-25-gyro-1-core-engine.md`) merged or on the same branch. Part 3 (Android) mirrors this plan and reads `GyroCopy` and the pill vectors created here; start Part 3 once Tasks 3 and 5 of this plan are on the branch.

**Why this boundary:** runtime and screens for one platform belong together because the screens are only verifiable against the coordinator's real state transitions, and both need the same iOS simulator test host. The Android twin is Part 3.

## Review Focus

1. **Camera connects while already recording:** logging opens a partial take immediately, the arming sheet waits until recording stops, and calibration is not offered mid-take. Test: `connectingDuringRecordingDefersTheSheet` in Task 3.
2. **App backgrounded while the arming sheet or calibration is open:** the session ends, calibration is invalidated with the connection-ended message, the restore is attempted and the sheet closes; returning starts a new session with a new sheet. Test: `backgroundingEndsTheSessionAndClosesTheSheet` in Task 3.
3. **Phone rotated during calibration:** the layout switches between portrait and landscape without resetting the step or the hold. Test: `rotationKeepsCalibrationProgress` in Task 10.
4. **VoiceOver user calibrates:** hold progress is announced at 25, 50 and 75 percent, each capture and completion are announced, and every control is reachable. Test: `ringAnnouncesProgressAndCaptures` in Task 7 and the accessibility walk in Task 10.
5. **Delete or share of a take that is still recording:** both are refused without touching the file; swipe-to-delete is not offered on an active take; Select mode cannot select it. Test: `activeTakeCannotBeSelectedOrDeleted` in Task 8.

```swift
// OpenCineGyro
public enum GyroPillKind: String, Sendable { case hidden, offline, armed, recording, saving, gaps, mountMoved, error }
public struct GyroPillState: Equatable, Sendable {
    public let kind: GyroPillKind
    public let stabilizationWarning: Bool
    public static func resolve(enabled: Bool, failed: Bool, armed: Bool, motionRunning: Bool, hasFirstSample: Bool,
                               activeTake: Bool, cameraRecording: Bool?, gapWarning: Bool, mountMoved: Bool,
                               stabilizationWarning: Bool) -> GyroPillState
}
// OpenCineGyroApple (extension of the coordinator)
public private(set) var pill: GyroPillState
public private(set) var setupSteps: [GyroArmingStep]      // non-empty = arming sheet shown; first is the current step
public var isArmed: Bool { get }
public func setupTurnOffStabilization()
public func setupKeepStabilization()
public func setupSkipCalibration()                         // arms uncalibrated (owner decision 2)
public func prepareForDisconnect() async                   // ends the session and awaits the restore, at most 3 s
```

Pill rule (fixture-backed; the spec says keep the compact uppercase pill and list the states): `hidden` when `!enabled && !failed`; `error` when `failed`; `mountMoved` when `mountMoved && activeTake`; `gaps` when `activeTake && gapWarning`; `recording` when `activeTake && cameraRecording == true`; `saving` when `activeTake`; `armed` when `armed && motionRunning && hasFirstSample`; otherwise `offline`. `stabilizationWarning` passes through except for `hidden` (false). Fixture columns: the ten inputs then `kind warning`; at least 16 rows covering each precedence step.

The coordinator feeds `GyroArmingMachine.update` on every adapter event, eligibility change and toggle change, and applies effects in order: `.writeStabilization` calls `adapter.writeStabilization` then `writeFinished`; `.presentSetup` sets `setupSteps`; `.persistPendingRestores` writes `preferences.pendingRestores`; `.sessionStarted` starts motion (the Task 2 logging start); `.sessionEnded` stops motion with the matching termination (`.disabled` when the toggle went off, `.disconnected` otherwise) and clears `setupSteps`; `.notice` sets `notice`. `setupTurnOffStabilization` and `setupKeepStabilization` call the machine and drop the stabilization step from `setupSteps`.

### Task 4: Ring calibration and drift in the coordinator

**Files:**

- Create: `Sources/OpenCineGyroApple/GyroCaptureCoordinator+Calibration.swift`, `Sources/OpenCineGyroApple/GyroCaptureCoordinator+Drift.swift`

**Interfaces:**

- Consumes: `GyroRingCalibration`, `GyroRingPhase`, `GyroRingEvent`, `GyroCalibrationInvalidation`, `GyroDriftDetector`, `GyroTakeSession.observeMountMoved`, `GyroPreferences.calibration(for:)`/`saveCalibration(_:for:)`.
- Produces:

```swift
public private(set) var ring: GyroRingPhase?               // nil = calibration not presented
public private(set) var ringCompletedSteps: Int
public private(set) var lastRingEvent: GyroRingEvent?      // views use it for the checkmark, haptic and announcement
public var canCalibrate: Bool { get }                      // adapter attached, providesLevel, connected
public var hasSavedCalibration: Bool { get }               // for the current camera
public func beginCalibration()                             // shows the intro (ring = .intro)
public func startRing()                                    // "Get started"
public func setupUseLastCalibration()                      // arming sheet link: keeps the saved calibration, closes the step
public func cancelCalibration()                            // closes; keeps any previous calibration; arms uncalibrated if in setup
public func finishCalibration()                            // "Done" on the complete screen
public private(set) var driftPromptPresented: Bool
public func recalibrateAfterDrift()                        // closes the prompt, beginCalibration()
public func dismissDriftPrompt()                           // "Not now": no further prompts this armed session
```

Rules:

- While `ring != nil`, subscribe `driver.startMotion`; each reading calls `GyroRingCalibration.observe` with the newest adapter level (`.level(down, at:)`). `.completed` saves the calibration for the camera id and sets `ring = .complete`.
- Invalidation (spec section 2, today's rules with new wording): camera id changes -> `.cameraChanged`; recording becomes true -> `.recordingStarted`; disconnect or `appDidEnterBackground` -> `.connectionEnded`.
- Drift: while armed with a saved calibration for this camera and `adapter.providesLevel`, keep a `GyroDriftDetector` fed from `startMotion` readings and adapter levels, only while a take is recording. On confirmation: `session.observeMountMoved(at:)` updates go through the store, `mountMovedInTake = true` (feeds the pill), one light haptic request flag for the view (`driftHapticToken += 1`). When that take's REC stops, present the drift prompt unless dismissed earlier in this armed session. The detector resets after `finishCalibration` and at each session start. Without calibration or level, drift is off.
