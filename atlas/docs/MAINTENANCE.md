# Maintaining the atlas

Read before changing registry entries, summaries, snapshots or tooling. Implementing an app
fix does not require touching the atlas unless it changed ownership, a dependency or a
copy relationship.

## What is authored and what is generated

| File | Kind | Rule |
|---|---|---|
| `repos/<id>/meta.json` | Authored facts | Edges, refs, products; for the platform (`opencine`) also `layers`, which assigns every Swift target and Gradle module a product layer. Validated by `atlas check`. |
| `repos/<id>/SUMMARY.md` | Authored map | Where to start reading and cross-repo gotchas only. |
| `repos/<id>/snapshots/<full sha>/` | Generated by `atlas graph build` | `snapshot.json`, `GRAPH_REPORT.md`, `graphify_labels.json`. Never hand-edit except labels. |
| `graphify-out/` | Generated, ignored | Full graphs and the merged navigation view. Never commit. |
| `.local/` | Machine-local, ignored | `checkouts.json`, task notes, overlays. |
| `compat/candidates.json` | Authored, statuses written by `atlas compat run` | Package candidates, consumer revisions and check recipes. |
| `compat/results/<id>.json` | Generated by `atlas compat run` | Last run: SHAs, toolchain, per-check result and sanitized log tail. `.inject-break.json` holds a gate proof. |
| `compat/archive/` | Historical | Records from before the one-repository consolidation (ADR 0010). Not validated or run. |

## Edge schema

Edges in `meta.json` are outgoing: `to` is what this repository needs or copies from.
Never record the inverse; `deps` and `impact` derive it.

| `kind` | Meaning | Test question | Propagates impact |
|---|---|---|---|
| `library` | Compiles or links the target's product | Is their code in my build output? | yes |
| `contract` | Implements or consumes an API/schema defined in the target | Do they own the schema I build against? | yes |
| `generates` | Checked-in output generated from the target's definitions | Is my committed code their output? | yes |
| `source-copy` | Source copied or synchronized from the target | Did these files start as their files? | yes (re-sync, review, rebuild) |
| `runtime` | Talks to the target at runtime, no build coupling | Do processes talk? | no (verify only) |
| `documents` | Prose about the target | Am I documentation of them? | no |
| `tests` | Validates the target's product without shipping it | Do I only check them? | no |

Required fields: `to`, `kind`, `status` (`live` or `candidate`), `confidence` (`confirmed`
needs `evidence.path` plus a full `evidence.source_commit`; otherwise `inferred`).
`source-copy` also needs `scope`, `mechanism` and `donor_revision` (a full SHA, or `null` when
the donor revision was never recorded). Optional: `platforms`, `ref` (a registered ref name),
`note`. A candidate repository never has, or is the target of, a `live` edge.

`source-copy` edges may form cycles (today Pocket and Nikon copy from each other, and
`opencine` holds UI extracted from Pocket while Pocket's branch consumes it). `atlas impact` puts every
repo of such a cycle in one wave and prints the cycle, because no order inside it can be
derived. Retiring copies removes the cycles. Build-kind cycles are errors.

An inferred edge guides a search; it never controls release order. With `--sources`,
`check` verifies that each confirmed edge's evidence file exists at its commit and, for
build kinds, that the manifest really declares the dependency (comments do not count).

## Summaries

A summary is a map, not a copy. Record how the repository connects to others, which changes
belong in it, where to start reading, and gotchas no single repository can state. Do not
restate build commands, version numbers or module layout; link to the source. Do not anchor
prose to "the latest commit". When a summary is re-read against source, set
`summary_review` (`source_commit`, `reviewed_at` in UTC). Only a person or agent who actually
re-read it moves that stamp.

## Routine

Run these when the trigger happens; there is no scheduler.

| Trigger | Action |
|---|---|
| Any atlas edit | `python3 -m unittest discover -s tests` and `python3 tools/atlas.py check` (CI runs both). With checkouts available, also `check --sources`. |
| A target or Gradle module was added to, renamed in or removed from OpenCine | Update `layers` in `repos/opencine/meta.json` (and `products` for a new product); `check` fails until every target and module has a layer. |
| A pinned source moved (`atlas stale` says outdated) | Decide whether the new commit is the baseline. If yes, update `refs`, re-run `check --sources`, and rebuild the snapshot if navigation matters for current work. |
| Ownership or dependency changed after an authorized merge | Update edges and refs; remove a `source-copy` edge only once the consumer really uses the package; re-read the summary and bump `summary_review`. |
| A package candidate is validated against consumers | Record the package SHA, consumer SHAs and check recipes in `compat/candidates.json`, run `atlas compat run <id>` and commit both files ([EXECUTION.md](EXECUTION.md#candidate-consumer-validation-ops-01)). |
| Navigation graph needed for a repo | `atlas graph plan <repo>@<ref>`, then `atlas graph build <repo>@<ref> --local-only`, one repo at a time. Commit the snapshot folder only. |
| Cross-repo navigation view needed | `atlas graph build --all --local-only`: each repository at the ref it builds OpenCine on (else its baseline), then a merged view of only those in `graphify-out/` that `atlas impact <symbol>` reads for call-site hints. About two minutes. Without Graphify it exits 3 and `impact` uses source search. |
| Community labels need better names | Edit `repos/<id>/snapshots/<sha>/graphify_labels.json`; rebuilds start from that file and keep existing names. No model labeling exists. |

## Graph provenance

Snapshots are keyed by full commit SHA and built from `git archive` of that commit, never from
a working tree, so they are clean by construction and different branches cannot overwrite each
other. `snapshot.json` records commit, symbolic ref, tree, scan configuration hash, tool
versions, build time, excluded classes and coverage. `atlas stale` reports a snapshot as
outdated when the scan configuration or Graphify version changes. Graph facts are navigation
hints; dependency facts come from manifests and authored evidence.

Known coverage gaps with Graphify 0.9.11 (absence of an edge is not absence of a call):

- Kotlin `external fun` declarations are not linked to their JNI exports. In the Pocket
  baseline graph the 21 `Java_com_opencapture_...` export symbols have no edge to any Kotlin
  node. Follow JNI by name search.
- Calls resolved only at runtime or by string (shader entry points, reflection, SwiftUI
  result-builder bodies, `#if`-conditional sources) may be missing or attributed loosely.
- About 8% of edges in each build are `INFERRED` by Graphify's extractor heuristics.
- Files excluded by class (see `coverage.excluded` in each `snapshot.json`) are absent,
  including Nikon's `reference/` tree.

## Writing style

No em dash characters anywhere, including generated reports (the Graphify adapter normalizes
them). `check` rejects em dashes and private machine paths in every tracked file.
